# Функциональные требования (Functional Requirements)

---

## A1. Приём данных

- **Приём HTTP-запросов**
    - Метод: `POST`
    - Формат: `multipart/form-data`
    - Протокол: HTTPS (TLS 1.3)
    - Источник: Web Application (React)

- **Приём медицинских изображений**
    - Поддерживаемые форматы: JPEG, PNG
    - Максимальный размер файла: 10 МБ
    - Валидация:
        - MIME-type
        - расширение файла

- **Приём текстовых симптомов**
    - Форматы: JSON, TXT
    - Максимальная длина: 1000 символов
    - Языки: русский, английский

- **Сохранение файлов**
    - Хранилище: AWS S3
    - Bucket: `medical-images-raw`
    - Структура хранения: `{userId}/{fileId}.{ext}`
    - Шифрование: AES-256

- **Сохранение метаданных**
    - СУБД: PostgreSQL
    - Таблица: `medical_data`
    - Поля:
        - `user_id`
        - `file_id`
        - `file_name`
        - `s3_url`
        - `uploaded_at`
    - Индексы: `user_id`, `uploaded_at`

- **Отправка сообщений**
    - Брокер: RabbitMQ
    - Очередь: `medical_data`
    - Формат сообщений: JSON (AMQP)
    - Payload:
        - `fileId`
        - `userId`
        - `s3Url`
        - `fileType`
        - `timestamp`

- **Валидация данных**
    - Проверки:
        - размер файла ≤ 10 МБ
        - MIME-type
        - расширение файла
    - Ошибка при нарушении: `400 Bad Request`

- **Аутентификация и безопасность**
    - JWT-аутентификация
    - Rate limiting: 100 запросов в минуту на пользователя
    - Политики CORS для web-приложения

## A2. Препроцессинг данных

- **Получение данных**
    - Источник: RabbitMQ
    - Очередь: `medical_data`
    - Формат сообщений: JSON

- **Загрузка файлов**
    - Источник: AWS S3
    - Bucket: `medical-images-raw`
    - Форматы файлов: JPEG, PNG

- **Препроцессинг изображений**
    - Размер входных данных: `224 × 224 × 3`
    - Тип данных: `float32`
    - Нормализация: ImageNet
    - Инструмент: OpenCV

- **Токенизация текста**
    - Модель: BERT base uncased
    - Максимальная длина: 128 токенов
    - Выходные данные:
        - `input_ids`
        - `attention_mask`
    - Инструмент: HuggingFace Tokenizer

- **Параметры нормализации**
    - Mean: `[0.485, 0.456, 0.406]`
    - Std: `[0.229, 0.224, 0.225]`
    - Диапазон значений: `[0, 1]`

- **Правила токенизации**
    - Vocabulary: 30 522 токена
    - Padding: right
    - Truncation: enabled

## A3. ИИ-анализ

- **Классификация изображений**
    - Модель: ResNet-50 (CheXNet)
    - Версия: v2.3.0
    - Требуемая точность: ≥ 95%
    - Результат: JSON с топ-3 диагнозами (softmax)

- **Анализ текста**
    - Модель: BERT base uncased (fine-tuned на медицинском корпусе)
    - Результат: JSON с топ-3 диагнозами

- **Генерация объяснений результатов**
    - Для изображений: Grad-CAM (PNG heatmap)
    - Для текста: SHAP (JSON)

- **Сохранение результатов анализа**
    - Redis: кэширование (TTL = 1 час)
    - PostgreSQL: постоянное хранение
    - Формат данных: JSON

- **Пороговые значения вероятности**
    - High confidence: ≥ 0.9
    - Medium confidence: 0.5 – 0.9
    - Low confidence: < 0.5

- **Управление версиями моделей**
    - ResNet-50: v2.3.0
    - BERT: v1.2.0
    - Поддержка A/B тестирования

## A4. Формирование отчёта

- **Генерация PDF-отчётов**
    - Формат: A4, portrait
    - Инструмент: PDFKit
    - Содержание:
        - топ-3 диагноза
        - вероятности
        - heatmap
        - метаданные пациента

- **Генерация HTML-отчётов**
    - Template engine: Jinja2
    - Styling: Bootstrap 5
    - Responsive layout

- **Интеграция с Clinic MIS**
    - Протокол: REST (JSON)
    - Endpoint: `POST /reports`
    - Retry: 3 попытки (exponential backoff)

- **WebSocket-уведомления**
    - События:
        - отчёт готов
        - ошибка генерации
        - отправка в MIS

- **Шаблоны отчётов**
    - HTML: Jinja2
    - CSS: Bootstrap 5
    - Layout: A4

- **Формат и доступность**
    - PDF: A4 portrait
    - HTML: соответствие WCAG 2.1 AA

- **Конфиденциальность данных**
    - Соответствие HIPAA
    - Соответствие GDPR
    - Шифрование:
        - TLS 1.3 (передача)
        - AES-256 (хранение)

## A5. Регистрация пользователя (IDEF3 P1)

- **Регистрация пользователя**
    - Поля формы: Email, пароль, ФИО
    - Валидация:
        - корректный email
        - пароль ≥ 8 символов

- **Проверка уникальности email**
    - Хранилище: PostgreSQL (`users`)
    - Ошибка при существующем email

- **Создание пользователя**
    - Хеширование пароля: BCrypt
    - Роль по умолчанию: Patient

- **Активация аккаунта**
    - Способ: переход по ссылке из письма
    - Сервис отправки: SMTP
    - Токен: JWT
    - Время жизни токена: 24 часа
